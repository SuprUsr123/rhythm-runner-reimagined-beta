# Geometry Dash 2.2 Canvas compatibility pass

This build extends the existing Rhythm Runner engine with a selected set of 2.2 gameplay and camera features. Rendering remains Canvas 2D. Shader triggers, particle triggers, shader pipelines, WebGL renderers, and GPU-only effects are deliberately excluded.

## Camera controls

| Feature | Object ID | Implemented behavior |
|---|---:|---|
| Camera Zoom | 1913 | Zoom from 0.4× to 3×, with duration and easing. |
| Static Camera | 1914 | Anchor to a target group, optional live follow, X/Y axis selection, follow easing, smooth-velocity modifier, exit, and instant exit. |
| Camera Offset | 1916 | X/Y offset tween with axis selection and easing. |
| Camera Rotate | 2015 | Absolute or additive rotation, easing, and 360-degree angle wrapping. |
| Camera Edge | 2062 | Clamp the selected left/right/top/bottom camera edge to a target group; target group 0 releases that edge. |
| Camera Mode | 2925 | Free-mode camera handling with configurable follow easing and padding. |
| Camera Guide | 2016 | Editor-only preview frame showing the requested zoom/aspect area; not a gameplay effect. |

Camera trigger settings are preserved through `.gmd` import/export. Static-camera exit and non-follow anchors are handled separately from follow mode so a fixed camera stays fixed after its entry tween finishes.

## Event triggers

| Feature | Object ID | Implemented behavior |
|---|---:|---|
| Event Trigger | 3604 | Parses and exports event-code lists, target group, Extra ID, player filter, touch/multi-trigger flags; matching events queue the target group. |

The engine currently raises only event codes that could be verified from the reference material:

- `64` — Checkpoint Respawn
- `75` — Player Reversed
- `76` — Fall Speed Low

Other event-code values in imported levels are preserved, but this build does not yet emit all of the 78 documented player/object events. Event links that depend on unsupported actions therefore will not fire yet. Extra ID filtering is enforced when an event has an associated material/control ID; player selection supports P1, P2, or either.

## Platformer mode

- Reads and writes the Geometry Dash platformer level flag (`kA22,1`).
- Adds left/right movement through A/D, arrow keys, and on-screen buttons; Space remains jump/hold.
- Uses acceleration and friction for horizontal movement and the existing solid/breakable collision grid for side collisions.
- Stops horizontal movement on solid side contact and implements the platformer Stop Move / Stop Slide behavior in Player Control triggers.
- Recognizes checkpoint object `2063`, activates it on contact, and respawns Player 1 at the latest activated checkpoint after death.
- Checkpoint object raw properties are retained during import/export so unimplemented options are not discarded.

Checkpoint respawn currently uses the checkpoint object's placed position and restores the player form, speed, gravity direction/multiplier, and horizontal direction recorded at activation. Optional checkpoint SpawnID/RespawnID/TargetPos/PlayerPos group-routing behavior is not simulated yet.

## Other 2.2 mechanics retained from the previous pass

- Reverse (`1917`), Gravity (`2066`), Player Control (`1932`), TimeWarp (`1935`), Teleport (`3022`), and End (`3600`).
- Existing 2.1 gameplay and rendering paths remain intact; classic auto-run is not changed by the platformer movement path.

## Validation

- `node --check` passed for the edited JavaScript files.
- Level-model tests passed for `.gmd`-style serialize/import round-trips covering the platformer flag, camera trigger settings, Event Trigger filters/event lists, and checkpoint raw properties.
- Direct simulator tests passed for checkpoint contact, leftward movement, and horizontal stopping against a solid wall.
- Browser-level smoke testing remains outstanding because the available headless Chromium process stalled even on a blank page in this environment.

## Explicit exclusions and remaining work

This is not complete 2.2 compatibility. Area triggers, keyframe/advanced follow, item/timer/random/sequence triggers, the full 78-event dispatch table, extended checkpoint spawn routing, dual-player platformer behavior, and some specialized platformer momentum/slope interactions remain unimplemented. Shader and particle trigger systems remain intentionally excluded, and no WebGL path has been introduced.
